# Major model families

CS5487 ■ Semester A, 2026/27

# 1 : ines

Linear models remain useful because they are:

▶ fast to train;

▶ easy to reproduce;

relatively easy to interpret;

▶ strong when the representation is informative.

They provide a clear test of whether additional model complexity is actually useful.

How this is used today

A pretrained representation followed by a linear classifier is a common way to test representation quality.

**Trees and boosting**

A decision tree repeatedly splits the feature space using simple rules such as:

$$ x_{j}<c\quad\mathrm{o r}\quad x_{j}\geq c. $$

▶ Trees capture nonlinear feature interactions.

▶ Random forests average many trees to reduce instability.

▶ Gradient boosting adds trees sequentially to correct current errors.

For tabular data, boosted trees are often an important comparison method.

**Neural networks**

A neural-network layer applies:

$$ \boldsymbol{h}^{(\ell+1)}=\phi\left(\boldsymbol{W}^{(\ell)}\boldsymbol{h}^{(\ell)}+\boldsymbol{b}^{(\ell)}\right). $$

The nonlinear function  $ \phi $ allows multiple layers to represent nonlinear relationships. Neural networks can learn:

representation + prediction

Greater capacity can model richer patterns, but usually requires more data and stronger regularization.

**Convolution and spatial locality**

A convolution applies the same local filter at many positions:

$$ y[t]=\sum_{s}w[s]x[t-s]. $$

This gives:

▶ local feature extraction;

parameter sharing across locations.

Typical uses include signals, images, volumes, and video.

![](http://maas-model-u2-ocr.oss-cn-beijing.aliyuncs.com/kms-data-manager%2F89dca47f45d846ed87dbdb8161db0fa6%2Fmedia%2F2ac01649428d4dd8b28b58d1b0b963d3.jpg?OSSAccessKeyId=LTAI5tNcMEY7TGXWsdNGEppS&Expires=1799244741&Signature=I9o9cNuKlnYilRhcaLVfHVKzRMw%3D)

the same local calculation is reused at every position

**Attention**

Attention allows one item to collect information from other items.

![](http://maas-model-u2-ocr.oss-cn-beijing.aliyuncs.com/kms-data-manager%2F89dca47f45d846ed87dbdb8161db0fa6%2Fmedia%2Fe15b9116029244e59110db2da87deb82.jpg?OSSAccessKeyId=LTAI5tNcMEY7TGXWsdNGEppS&Expires=1799244741&Signature=7ftrAduYN6eXDLOSveFkxWt3puk%3D)

The three roles are:

▶ query: what information is needed;

▶ key: what each item offers for matching;

value: the information that may be combined.

**Scaled dot-product attention**

Collect queries, keys, and values into Q, K, and V:

$$  Attention(Q,\boldsymbol{K},\boldsymbol{V})=softmax\left(\frac{Q\boldsymbol{K}^{\top}}{\sqrt{d}}\right)\boldsymbol{V}. $$

The computation is:

$ QK^{\top} \rightarrow $ matching scores  $ \rightarrow $ normalized weights  $ \rightarrow $ weighted values.

Attention therefore builds a representation by deciding which other items matter most.

**Representation learning**

A representation is a learned numerical description:

$$ z=f_{\theta}(x). $$

Common learning signals include:

▶ reconstruction;

predicting hidden or future content;

▶ contrastive learning;

supervised prediction.

The goal is:

preserve information useful for later tasks

How this is used today

PCA learns a linear representation; neural networks can learn nonlinear representations.

**Pretraining and transfer**

Pretraining learns reusable parameters from a large source dataset.

A target task can then:

▶ freeze the representation and train a new head;

▶ fine-tune the full model;

▶ update only a small adapter;

▶ use prompting when the model supports it.

Foundation models extend this idea by pretraining broadly for reuse across many tasks. For a course project, adapting an existing model is usually more realistic than training one from scratch.

**Multimodal models**

A multimodal model combines several data types, for example:

text + images + audio.

The key problem is to learn useful relationships across modalities. Potential benefits:

▶ complementary information;

▶ reusable representations;

reduced task-specific labeling.

The useful project question is whether the additional modality produces measurable improvement.

**Generative models**

Generative models describe how observations may be produced. Common forms include:

▶ autoregressive: predict the next element from previous elements;

▶ latent-variable: explain observations using hidden variables;

diffusion: learn to reverse a gradual noising process.

For example:

$$ p(x)=\prod_{t}p(x_{t}\mid x_{<t}) $$

is an autoregressive factorization.

GMMs from earlier weeks are already latent-variable generative models.

**Choosing a project**

**From idea to testable project**

Weak:

"Apply deep learning to medical images."

Stronger:

Does a pretrained representation improve lesion classification over a linear model and a small CNN when only 20% of labels are available?

A project direction should identify:

▶ the task;

▶ the dataset;

▶ the comparison;

▶ the performance measure;

▶ the main constraint or limitation.

**Dataset selection**

Before choosing the model, check the data.

What is one independent sample?

What is the correct train/test split unit?

▶ Are labels reliable?

Are important groups represented?

▶ Can related samples leak across splits?

**Common mistake**

Frames from the same video or records from the same patient should usually not be split randomly across training and testing.

**Performance measures follow the goal**

<table><tr><td>Goal</td><td>Useful measures</td><td>Common warning</td></tr><tr><td>balanced classes</td><td>accuracy; class-averaged score</td><td>inspect each class</td></tr><tr><td>rare events</td><td>sensitivity; precision</td><td>accuracy can mislead</td></tr><tr><td>numerical prediction</td><td>absolute or squared error</td><td>scale and outliers matter</td></tr><tr><td>image regions</td><td>overlap and boundary error</td><td>empty regions need a rule</td></tr><tr><td>search or ranking</td><td>top- $ k $ relevance</td><td>candidate set matters</td></tr><tr><td>probabilities</td><td>probability error, calibration</td><td>averages hide subgroups</td></tr></table>

A performance measure should reflect the decision the model is intended to support.

**Controlled comparison ladder**

A useful study compares increasing levels of complexity:

1. trivial reference;

2. simple classical model;

3. strong standard method;

4. proposed model or adaptation.

Keep the data split, preprocessing, evaluation, and training budget as comparable as possible. Then change one main factor at a time:

one controlled change  $ \rightarrow $ one interpretable conclusion

**Compute-aware project scope**

Estimate cost before implementation:

dataset size and preprocessing time;

memory requirements;

▶ training time per run;

▶ number of baselines and repeated runs;

▶ inference cost if deployment matters.

When resources are limited, use a smaller model, fixed pretrained features, or a smaller controlled dataset.

A completed controlled experiment is more useful than an unfinished large one.

**Error analysis**

Average scores do not explain model behavior.

Inspect:

▶ class-specific errors;

▶ high-confidence mistakes;

▶ difficult acquisition conditions;

▶ cases where methods disagree;

▶ sensitivity to preprocessing.

The purpose is to identify:

where and why the model fails

**Possible project directions**

Tabular: linear models versus boosted trees.

▶ Time series: anomaly detection under noise or missing values.

Text: count-based versus pretrained representations.

Images: transfer learning under limited labels.

▶ Signals: handcrafted versus learned features.

▶ Scientific data: robustness across locations, devices, or seasons.

Multimodal: measure whether an additional modality adds useful information.

The project question should be narrower than the application domain.

**Repeatable experiments**

Another person should be able to reconstruct the reported result. Record:

dataset version and split;

▶ preprocessing;

▶ software environment;

▶ model configuration;

▶ random seeds;

hardware;

results from relevant runs.

result  $ \longleftrightarrow $ exact configuration

**Ethics and responsible scope**

Before using a dataset or model, ask:

Do we have permission to use the data?

▶ Could labels contain historical or measurement bias?

Who is affected by false positives and false negatives?

Does the proposed use go beyond the available evidence?

Is human review needed?

**Common mistake**

Publicly downloadable does not automatically mean unrestricted, representative, or ethically appropriate.

**Project readiness**

Before implementation, the group should be able to state:

1. Question: one testable claim.

2. Data: sample unit, labels, and split strategy.

3. Methods: baseline and main comparison.

4. Evaluation: primary measure and error analysis.

5. Resources: compute estimate and fallback plan.

6. Risks: leakage, ethics, licensing, and limitations.

If one item is unclear, resolve it before increasing model complexity.

**Summary**

Three principles organize this lecture:

1. Match structure: choose models that fit the data and learning signal.

2. Control comparisons: change one important factor at a time.

3. Design for evidence: evaluation, error analysis, and reproducibility matter as much as the model.

sharp question + controlled experiment > oversized model
