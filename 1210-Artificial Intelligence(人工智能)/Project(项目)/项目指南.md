# 课程项目

## 1. 项目安排

建议 3 人一组，但也允许 1 或 2 人一组。项目占课程总成绩的 30%；组队时请合理评估工作量。所有组员获得相同的项目成绩，无任何例外。

### 1.1 提交内容

**项目提案**【占项目成绩 20%，总评成绩 6%】——截止日期：2026 年 10 月 15 日 23:59（北京时间）

- 小组成员名单（姓名、学号、一个联系邮箱）。
- 你们计划做什么：
  - 打算选择哪个题目/问题，为什么？
  - 解决该问题的初步方案是什么？
  - 打算如何评估你们的方案？换言之，计划使用什么数据集/基准测试实例，与哪个现有算法进行对比？
  - 如果项目使用大语言模型（LLM）：使用哪个模型、如何访问、预计调用次数（见第 3 节）。
- 格式：一页 PDF，采用第 1.3 节的标准格式。无需摘要和参考文献。每组在 Canvas 上提交一次。

> **Canvas 提交入口补充信息**（2026-10-14 记录，英文原文见文末附录）：
> - **提交窗口**：2026-09-24 09:00 开放，至 **2026-10-22 23:59**。⚠️ 与本指南正文"10 月 15 日截止"不一致——请在 Canvas 作业页面确认 Due 字段或询问助教，勿拖到最后一刻。
> - **尝试次数**：不限（Unlimited Attempts Allowed），提交后可反复更新。
> - **文件格式**：Word（.docx）或 PDF 均可（"one-page document (docx or pdf)"）。
> - **提案必须用英文撰写**（"The proposal has to be written in ENGLISH"）。
> - Canvas 页面写格式遵循 "Sec 1.2 of Course Project"，实指本文件第 1.3 节的格式要求（Times New Roman 12pt 等），疑为引用笔误。

**项目中期检查**【占项目成绩 10%，总评成绩 3%】——截止日期：2026 年 11 月 19 日 23:59（北京时间）

中期检查的目的，一是督促你们尽早启动项目，二是让助教有更实质的内容可以给予反馈。

- 代码：在线代码仓库的链接（见第 1.2 节），须包含：
  - 在你们选定的数据集/基准测试实例上的评估；
  - 项目所需的其他程序。
- 报告草稿（格式同提案，不超过期末报告的页数限制）：
  - 问题描述与方法/思路的动机；
  - 方法/思路的设计；
  - 初步结果。

**期末项目**【占项目成绩 70%，总评成绩 21%】——截止日期：2026 年 12 月 3 日 23:59（北京时间）

- 期末项目报告（50 分），采用第 1.3 节的标准格式，正文 4 页（参考文献不计）。请包含以下（或等价的）信息：
  - 问题/任务的动机与阐述（10 分）
  - 方法的合理性与阐述（15 分）
  - 洞见与结果（15 分）
  - 表达呈现（写作、图表等）（10 分）
- 在线代码仓库的链接，并注明用于评分的 commit hash 或 tag，以便复现项目报告中的结果（20 分）：
  - 代码：正确性、设计（15 分）
  - 文档：README、类/函数说明、代码内注释（5 分）
- 详情见第 1.2 节。

### 1.2 代码提交说明（在线代码仓库）

代码应托管在在线 Git 仓库中，例如 Gitee、GitHub 或 GitLab（在中国大陆 Gitee 的可访问性最稳定）。仓库应包含：

- **README**：概述代码的用途和任务；环境配置方法（Python 版本、requirements.txt 或 environment.yml）；复现报告中每个结果的确切命令（数据准备、训练/评估、绘图）及其预期输出和运行时间。
- **全部代码**：用于复现期末报告结果的所有代码（包括数据预处理、模型或启发式算法定义、训练/评估流水线，视项目具体要求而定）。
- **详细注释**：每个模块和函数的作用（docstring），以及代码内的注释。
- **数据**：小数据集或下载脚本直接放入仓库；大文件通过稳定链接提供。**严禁将 API 密钥或其他凭据提交到仓库；应从环境变量中读取。**
- 仓库应自包含，在新机器上开箱即可运行。

**提交方式**：将仓库 URL 和 commit hash（或 tag 名，如 milestone 和 final）粘贴到 Canvas 作业中。仓库必须公开。我们只对提交的那个 commit 评分；截止时间后推送的更改不予考虑。

### 1.3 书面材料格式（提案、中期草稿、期末报告）

所有书面材料遵循以下格式要求：

- 字体：Times New Roman ｜ 字号：12 磅 ｜ 页边距：四周各 2.5 cm ｜ 行距：单倍行距
- 纸张 A4，以 PDF 提交。图表及图注计入页数限制；期末报告的参考文献列表不计。
- 页数限制：提案 1 页；期末报告 4 页（参考文献不计）。
- 不要求使用模板：在 Word、LibreOffice 或 LaTeX 中按上述数值设置即可。超页数或不符格式的提交将在"表达呈现"一项扣分。

## 2. 项目题目

每个预设题目都有单独的文档说明。也欢迎你们根据自己的研究兴趣/背景选择其他题目。

1. **基于大语言模型的启发式算法自动设计**（PDF）。将启发式算法的设计视为一个搜索问题，遵循 FunSearch 的思路用 LLM 对程序空间进行搜索；方向包括新问题（TSP、流水车间调度、CVRP）、对 FunSearch 的改进、以及向机器学习任务的迁移。需要 LLM 访问；见第 3 节。
2. **面向加密推理的自举放置自动化**（PDF）。决定在神经网络的计算图的哪些边上放置同态加密中代价高昂的自举（bootstrapping）操作，在一系列输入 level 下，保证每个算子有足够的 level 并最小化预估延迟；对象为一个 MLP 模块和一个注意力模块。属于搜索与优化类题目；无需 LLM。
3. **神经谱容量作为架构设计启发式**（PDF）。使用提供的 NSC 打分器、归档的训练结果和评估框架，研究 Transformer 中的一种计算图机制。提出有动机的打分修改，并在排序和预算约束的架构选择任务上与 NSC、资源用量及随机选择等基线对比。核心实验在笔记本电脑上即可运行，无需训练或 LLM API。MoE、注意力状态、循环结构和超连接（hyperconnections）为可选扩展，需配备合适的验证。

## 3. 计算资源

- **LLM 访问**。今年不提供 LLM API 额度。如果项目使用 LLM，请自行安排访问方式并在提案中说明（模型、提供商或本地部署、预计调用次数）。两种常见选择：
  1. 使用中国大陆可访问的商用 API（例如 DeepSeek、阿里云百炼上的 Qwen、GLM 或 Kimi）；在确定方案前先估算项目所需的调用次数和费用；
  2. 用 Ollama 或 vLLM 在本地运行开源权重模型（例如 7B–14B 规模的 Qwen 模型），使用笔记本电脑或实验室 GPU。
- **GPU**。若使用 API 托管的 LLM，预设题目在普通笔记本上即可完成；只有在本地部署模型或训练神经网络时才需要 GPU。若干国内平台提供免费笔记本 GPU 额度（例如百度 AI Studio 和阿里 ModelScope）；请查阅其当前条款。

### Course Project 原文

**1. Project Logistics**

We recommend project groups of 3 students, but groups of 1 or 2 are also allowed. The project is worth 30% of your course grade; please be mindful of the workload when forming teams. All team members share the same project grade with no exceptions.

**1.1 What to submit**

Project proposal [20% of project grade, 6% of total grade] — Due Oct 15, 2026, 11:59 pm BJT

- Who is in your group (names, student IDs, and one contact email).
- What do you plan to do:
  - Which topic/problem are you planning to choose and why?
  - What is your tentative plan for solving the problem?
  - How do you plan to evaluate your solution? In other words, what dataset/benchmark test instances do you plan to use, and what existing algorithm do you plan to compare against?
  - If your project uses a large language model (LLM): which model, how you will access it, and the expected number of calls (see Section 3).
- Format: a single PDF of one page in the standard format of Section 1.3. No abstract and no reference list. One submission per group on Canvas.

Project milestone [10% of project grade, 3% of total grade] — Due Nov 19, 2026, 11:59 pm BJT

The purpose of the milestone is to encourage you to get started on the project early, and for the TAs to have something more substantial to give feedback on.

- Code: the link to your online code repository (see Section 1.2), containing
  - evaluation on the dataset/benchmark test instances you chose;
  - any other programs required by your project.
- Report draft (same format as the proposal, within the final-report page limit):
  - problem description and motivation of your method/approach;
  - design of your method/approach;
  - preliminary results.

Final project [70% of project grade, 21% of total grade] — Due Dec 3, 2026, 11:59 pm BJT

- Final project report (50 points), in the standard format of Section 1.3, 4 pages excluding references. Please include the following information (or equivalent):
  - Motivation & explanation of problem/task (10 points)
  - Appropriateness & explanation of your method (15 points)
  - Insights + results (15 points)
  - Presentation (writing, figures, etc.) (10 points)
- The link to your online code repository, with the commit hash or tag to be graded, for reproducing the results in the project report (20 points):
  - Code: correctness, design (15 points)
  - Documentation: README, class/function descriptions, comments in code (5 points)
- See Section 1.2 for details.

**1.2 Instruction on code submission (online code repository)**

Code should be hosted in an online Git repository, for example, on Gitee, GitHub, or GitLab (Gitee is the most reliably reachable from Mainland China). Your repository should include:

- A README with a high-level summary of what the code is about and what the task is; how to set up the environment (Python version, requirements.txt or environment.yml); and the exact commands that reproduce every result in your report (data preparation, training/evaluation, plotting), with the expected output and running time.
- All the code to reproduce your results in the final report (including data preprocessing, model or heuristic definition, and the train/evaluation pipeline, depending on the specifications of your project).
- Detailed comments: what each module and function does (docstrings), and comments in the code.
- Data: small datasets or download scripts inside the repository; large files through a stable link. Never commit API keys or other credentials; read them from environment variables.
- The repository should be self-contained and runnable as it is on a fresh machine.

How to submit: paste the repository URL and the commit hash (or a tag name, e.g. milestone and final) into the Canvas assignment. The repository must be public. We grade the submitted commit; changes pushed after the deadline are not considered.

**1.3 Format of written submissions (proposal, milestone draft, final report)**

- Font: Times New Roman • Font size: 12 point • Margin: 2.5 cm all round • Spacing: single-line spacing
- Paper size A4, submitted as a PDF. Figures, tables, and captions count toward the page limit; the reference list of the final report does not.
- Page limits: proposal, 1 page; final report, 4 pages excluding references.
- No template is required: set these values in Word, LibreOffice, or LaTeX. Submissions that exceed the page limit or do not follow the format will be marked down under Presentation.

**2. Project Topics**

Each pre-specified topic is described in its own document. Feel free to choose a different project topic based on your research interests/background.

1. **Automated Heuristic Design via Large Language Models** (PDF). Treat the design of a heuristic as a search problem and use an LLM to search over programs, following FunSearch; directions include new problems (TSP, flow shop, CVRP), enhancements to FunSearch, and adaptation to machine-learning tasks. Requires LLM access; see Section 3.
2. **Automated Bootstrapping Placement for Encrypted Inference** (PDF). Decide which edges of a neural network's computation graph to place the expensive bootstrapping operations of homomorphic encryption to ensure every operator has enough levels and minimize estimated latency, for an MLP block and an attention block over a range of input levels. A search and optimization topic; no LLM needed.
3. **Neural Spectral Capacity as a Heuristic for Architecture Design** (PDF). Study one computational-graph mechanism in a Transformer using a supplied NSC scorer, archived trained outcomes and an evaluation harness. Develop a motivated score modification and test ranking and budgeted architecture selection against NSC, resource and random-selection baselines. The core runs on a laptop without training or an LLM API. MoE, attention state, loops and hyperconnections are optional extensions requiring suitable validation.

**3. Compute Resources**

- **LLM access.** No LLM API credits are provided this year. If your project uses an LLM, arrange your own access and describe it in the proposal (model, provider, or local setup, expected number of calls). Two common options:
  1. a commercial API from a provider reachable in Mainland China (for example, DeepSeek, Qwen on Alibaba Cloud Model Studio, GLM, or Kimi); estimate the number of calls your your project needs and its cost before you commit to a design;
  2. An open-weight model run locally with Ollama or vLLM (for example, a Qwen model in the 7B to 14B range) on a laptop or lab GPU.
- **GPUs.** With an API-hosted LLM, the pre-specified topics run on an ordinary laptop; a GPU is needed only if you host a model locally or train neural models. Free notebook GPU quotas are offered by several Mainland platforms (for example, Baidu AI Studio and Alibaba ModelScope); check their current terms.
